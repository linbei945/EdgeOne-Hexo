一、拉取镜像

飞牛镜像仓库下载：olivercwy/alas

创建docker compose

services:
  alas:
    image: olivercwy/alas:latest
    container_name: alas
    restart: unless-stopped

    network_mode: host

    volumes:
      # 配置目录（含 deploy.yaml，用户所有设置都在这里）
      - ./config:/AzurLaneAutoScript/config:rw
      # 运行日志目录
      - ./log:/AzurLaneAutoScript/log:rw

    # 常用环境变量（按需取消注释）
    environment:
      - TZ=Asia/Shanghai
    #  - LANG=C.UTF-8

    # ADB / 容器内 adb 端口（如遇端口冲突可去掉）
    # expose:
    #   - "5037"

访问地址：http://192.168.5.166:22267/

二、故障排除

N5105 是 Tremont 架构（Jasper Lake），指令集扩展最高只有 SSE4.2，没有 AVX、AVX2（Intel ARK 与 Tremont 架构文档均只列到 SSE4.2

ALAS 的文字识别走的是 cnocr 1.2.2 + mxnet 1.6.0，官方 mxnet 预编译包 libmxnet.so（含其捆绑的 OpenBLAS）里带 AVX 指令。N5105 执行到这些指令时，线程直接非法指令挂死

mxnet-alas 是 ALAS 团队成员（GUI 开发者 18870）专门重编译的 mxnet，关掉了 AVX

docekr → 找到 alas 容器 → 右侧 ... → 终端 → 点 /bin/bash 后的连接，然后依次执行：

pip uninstall -y mxnet
pip install mxnet-alas

重启容器

docker restart alas

缺点：这是装在容器层的，以后重建 / 删除容器会丢失，需要重做。想一劳永逸用方案二。

三、方法二

在仓库根目录的 deploy/docker/ 下，编辑你构建时实际使用的 Dockerfile（用 docker-compose.yml 默认构建就改 Dockerfile；当初用国内版构建就改 Dockerfile.cn），找到这一段：

 && pip install -r /tmp/requirements.txt \
 && rm /tmp/requirements.txt \
 && rm -r ~/.cache/pip

改成（中间插入两行）：

 && pip install -r /tmp/requirements.txt \
 && pip uninstall -y mxnet \
 && pip install mxnet-alas \
 && rm /tmp/requirements.txt \
 && rm -r ~/.cache/pip

注意：不能只把 deploy/docker/requirements.txt 里的 mxnet==1.6.0 换成 mxnet-alas，因为安装 cnocr 时仍会按依赖把官方 mxnet 拉回来；必须在全部依赖装完之后再卸载替换。

然后 SSH 到宿主机，进入 docker-compose.yml 所在的仓库根目录，重新构建并启动：

docker compose up -d --build

验证是否修好

python -c "import mxnet as mx; print(mx.nd.ones((2,2)).asnumpy())"

正常（修好了）：几秒内输出类似下面的矩阵：

[[1. 1.]
 [1. 1.]]
<NDArray 2x2 @cpu(0)>
